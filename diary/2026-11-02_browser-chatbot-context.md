# Browser chatbot context, second slice

The first mission 134 commit exposed a bounded read-only browser API and a searchable text report. Today I expanded the same pure projection to show measured levels for pool and wet-hall tanks, individual day tanks, aggregate chemical store totals (the world has no separate readings for the physical bulk vessels), six boiler controllers, Olympic filter and discharge meters, and the Wash-O-Tron's alarm windows and raw admission inputs. `getConnections(ref)` now follows the room schematics and Olympic plumbing to name links, endpoints, related equipment refs and valves with their live positions.

A fresh headless Chrome profile against the shared dev server confirmed 339 indexed records, 218 with live state, a running Olympic pump, 14 links from its pump-set node, the suction valve's OPEN reading in the searched report, a working inspection link and an off switch that makes API queries return null. I could not test Claude, Gemini or ChatGPT extensions: the available computer-use browser surface refused new Chrome and in-app browser tabs. The TODO keeps extension testing and remaining alarm and machinery readers open. Targeted model tests covered tank changes, pit inhibit, wash HOLD and lockout, boiler and meter readings, and connected valve state; the full project checks are the commit gate.

After that commit I added PLANT REPORT to the default Esc-menu GAME rack and Copy Plant Report to its plain fallback. Both call the same browser report builder with a 500-item bound and respect the local off switch. A headless Chrome run with `?menu=plain` clicked the button and captured a 46 KB report including P-101A and the Wash-O-Tron. The default rack's new control is included in the settings-panel and layout tests. Extension testing and additional model readers remain open.
